## نقطه‌ی توقف و گام بعد

1. صاحب وبلاگ هر سه تکه‌ی کیت ۵ را از `kit.html` در سه زبانه‌ی ویرایش قالب جای‌گذاری می‌کند (گام ۲ کیت). به مقاله‌ها و صفحه‌ی «درباره» دست نمی‌زند.
2. صفحه‌ها از بیرون دوباره بررسی می‌شوند: صفحه‌ی اول، مقاله‌ها، هفت دسته، آرشیو و «درباره». نسخه‌ی روی وبلاگ از commit نشانی‌های jsDelivr پیداست: `84deb38` کیت ۲، `f490e61` کیت ۳، `2a42eb3` کیت ۴ و `23d29aa` کیت ۵. Firecrawl در حالت خواندن متن باید دست‌کم ۱۲ ثانیه صبر کند (`waitFor: 12000`)، چون قالب تا ۱۰ ثانیه منتظر CSS می‌ماند.
3. صاحب وبلاگ صفحه‌ی اول و یک مقاله را روی گوشی و رایانه‌ی خودش می‌بیند؛ ظاهر سربرگ، کره و تصویر بالای مقاله‌ها از بیرون سنجیدنی نیست.
4. نتیجه در [گزارش آزمون](TEST_REPORT.md) ثبت می‌شود و هر رفتار پیش‌بینی‌نشده‌ی تازه‌ی بلاگفا در [نقشه‌ی راه](DEVELOPMENT_ROADMAP.md) می‌آید و رفع می‌شود.

## ادامه دادن کار

```bash
cd blogfa
npm install
npm run qa                    # ساخت، پیش‌نمایش و همه‌ی آزمون‌ها، هم قالب درون‌خطی و هم قالب CDN
npm run qa:cdn                # فقط پیش‌نمایش CDN و آزمون‌هایش (check، cdntest، behaviour، validate، a11y و interact با --cdn)
npm run behaviour             # فقط رفتارهایی که وبلاگ زنده نشان داد (آرشیو، دسته‌ها، نوار تبلیغ، صفحه‌ی درباره)؛ CSS دیررس با: node tools/behaviour.mjs --cdn
node tools/visual.mjs         # مقایسه‌ی تصویری با مرجع؛ پس از تغییر عمدی ظاهر: --update
node tools/docs.mjs           # ساخت HTML راهنماها
node tools/kit.mjs            # ساخت کیت نصب
```

**تغییر CSS یا JavaScript:** فایل‌های `dist/cdn` نام‌هایی از هش محتوایشان دارند و تکه‌های قالب به commit قفل‌اند. پس از هر تغییر: `node tools/build.mjs`، commit و push پوشه‌ی `dist/cdn`، گذاشتن SHA آن commit در `cdn.json`، `node tools/build.mjs` دوباره (تکه‌ها فقط وقتی نوشته می‌شوند که آن commit همه‌ی فایل‌ها را بایت‌به‌بایت داشته باشد و روی GitHub باشد)، و commit تکه‌ها. صاحب وبلاگ بعد از آن باید تکه‌های تازه را دوباره جای‌گذاری کند.

آزمون‌های مرورگر به Playwright نیاز دارند. اگر Playwright جهانی نصب شده است، فرمان‌ها را با `NODE_PATH=$(npm root -g)` اجرا کنید.

**قاعده‌ی کیفیت:** هر تغییری که یک آزمون را رد کند یا تصویر مرجع را بی‌دلیل عوض کند، اصلاح یا برگردانده می‌شود. فقط کامیتی که همه‌ی آزمون‌ها رویش گذشته‌اند «آخرین نسخه‌ی سالم» این سند می‌شود.
