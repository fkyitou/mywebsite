# گزارش آزمون: نسخه‌ی ۲ کیت

**تاریخ اجرا:** ۴ نوامبر ۲۰۲۶، از ۲۱:۳۳ تا ۲۲:۳۳ به وقت جهانی (بامداد ۱۴ آبان ۱۴۰۵ به وقت تهران). نسخه‌ی آزموده: قالب CDN نسخه‌ی ۲ کیت، که CSS و JavaScript را از commit `84deb38` روی jsDelivr می‌گیرد، و قالب درون‌خطی که پیش‌نمایش و آزمون‌ها از آن هم ساخته می‌شوند.

**مهم‌ترین نکته:** تنها آزمونی که تا این لحظه روی خود بلاگفا انجام شده، تلاش صاحب وبلاگ برای ذخیره‌ی کیت نسخه‌ی ۱ است. بلاگفا تکه‌ی ۱ آن را (۳۰۹ کیلوبایت، و ۲۵۳ کیلوبایت در نسخه‌ی سبک) با پیام «حجم قالب بسیار بالا است» نپذیرفت. نسخه‌ی ۲ برای همین ساخته شد و هنوز روی بلاگفا ذخیره نشده است. بقیه‌ی آزمون‌ها روی «پیش‌نمایش» اجرا شده‌اند، یعنی نسخه‌ای از وبلاگ که `tools/preview.mjs` با پر کردن قالب و ده مقاله، به همان روشی که بلاگفا برچسب‌ها را پر می‌کند، روی همین رایانه می‌سازد. فقط سه بررسی بخش «بررسی‌های بیرونی» از بیرون این رایانه انجام شده‌اند.

روش هر آزمون با جزئیات در [گزارش کنترل کیفیت](docs/06-qa-report.md) آمده است.

همه‌ی آزمون‌های مرورگر پس از آخرین تغییر قالب (شناسه‌ی `an-script`، بخش «یافته‌ها») دوباره اجرا شدند، به وقت جهانی: قالب CDN از ۲۱:۵۴ تا ۲۲:۱۱، قالب درون‌خطی از ۲۲:۱۱ تا ۲۲:۲۸، و آزمون تعامل قالب CDN، پس از اصلاح آزمون «بازگشت به بالا»، از ۲۲:۲۸ تا ۲۲:۳۳. کیت نصب پس از همان تغییر قالب ساخته و آزموده شد.

مقایسه‌ی تصویری (`node tools/visual.mjs`) دوباره اجرا نشد. ظاهر صفحه‌ها در این دور تغییر نکرده است و یکی بودن ظاهر قالب CDN با قالب درون‌خطی را آزمون ایستای «ساختار و کد یکسان» می‌سنجد، نه مقایسه‌ی تصویر. تصویرهای مرجع آن از پیش از تغییر عمدی سربرگ نسخه‌ی B در دور قبل مانده‌اند و باید پس از بازبینی با `--update` تازه شوند.

## ۱۸۸ آزمون سازگاری دقیقاً چه می‌سنجند

**۱۳۸ آزمون ایستا،** روی متن خود فایل‌ها، در هر اجرای `check.mjs`:

- **قالب درون‌خطی و سبک (۲۳ آزمون برای هر کدام):** هر سه برچسب نگه‌دارنده‌ی قالب بلاگفا (`<blog:PostTemplate>`، `<blog:ArchiveTemplate>`، `<blog:PageTemplate>`) هست؛ در هر قالب فقط برچسب‌ها و بلوک‌های مستند بلاگفا به کار رفته و بلوک‌ها درست باز و بسته شده‌اند؛ هیچ کدی که بلاگفا مسدود می‌کند نیست (انتقال به نشانی دیگر، پاپ‌آپ، `eval`، `document.write`، `atob`، کد مبهم‌شده، شبکه‌ی تبلیغاتی، اسکریپت بیرونی)؛ نام سازنده هست؛ زبان و جهت صفحه `fa` و `rtl` است.
- **قالب CDN و CDN سبک (۴۴ آزمون برای هر کدام):** همان آزمون‌ها، به‌جز اینکه در هر قالب دقیقاً یک اسکریپت و یک CSS بیرونی هست، هر دو از نشانی jsDelivr قفل‌شده به commit؛ `integrity` هر کدام همان SHA-384 فایل `dist/cdn` است و `crossorigin="anonymous"` دارد؛ بارگذار همان نشانی و سه نشانی پشتیبان را دارد؛ ساختار صفحه بیرون از CSS و JavaScript با قالب درون‌خطی یکی است؛ فایل CSS و فایل JavaScript بایت‌به‌بایت همان کد درون‌خطی‌اند؛ و هر تکه زیر بودجه‌ی ۶۰ کیلوبایت است.
- **چهار آزمون سراسری:** commit نام‌برده در `cdn.json` همه‌ی فایل‌های `dist/cdn` را بایت‌به‌بایت دارد؛ آن commit روی GitHub است و jsDelivr می‌تواند بخواندش؛ قالب تأییدنشده‌ای در `dist/` نیست؛ و در شش فایل `dist/cdn` هیچ کدی که بلاگفا مسدود می‌کند نیست.

**۵۰ آزمون مرورگر،** روی پیش‌نمایش در Chromium: ۲۵ صفحه (صفحه‌ی اول، ده مقاله، هفت موضوع، درباره، آرشیو، فهرست نوشته‌ها در نسخه‌ی A، و چهار صفحه‌ی نمونه در نسخه‌ی B) در دو اندازه‌ی دسکتاپ ۱۴۴۰×۹۰۰ و موبایل ۳۹۰×۸۴۴. در هر صفحه: اسکریپت‌های قالب کامل اجرا شده‌اند، صفحه پیمایش افقی ندارد، آزمایشگاه مقاله ساخته شده و خطا نشان نمی‌دهد، هر جدول داده نمودار دارد، نام سازنده دیده می‌شود و کنسول مرورگر خطایی ندارد. با `--cdn` این هم سنجیده می‌شود که هر دو فایل از نشانی اصلی رسیده‌اند. این محیط به jsDelivr راه ندارد، پس `tools/cdnroute.mjs` درخواست‌های نشانی‌های jsDelivr را با فایل‌های `dist/cdn` و سرآیند CORS پاسخ می‌دهد تا مرورگر کد یکپارچگی را واقعاً بررسی کند.

## آنچه این آزمون‌ها نمی‌سنجند

این‌ها فقط روی خود بلاگفا، پس از نصب قالب، آزمودنی‌اند:

| رفتار بلاگفا | وضعیت |
|---|---|
| سقف اندازه‌ی هر زبانه‌ی ویرایش قالب | تکه‌های ۳۰۹ و ۲۵۳ کیلوبایتی نسخه‌ی ۱ رد شدند. سقف اعلام نشده است؛ قالبی که پیش از آن روی وبلاگ نصب بود حدود ۱۰۵ کیلوبایت است. تکه‌های نسخه‌ی ۲ (بزرگ‌ترینشان حدود ۲۵ کیلوبایت) هنوز روی بلاگفا ذخیره نشده‌اند |
| آیا بلاگفا برچسب‌های `<link>` و `<script>` بیرونی و ویژگی‌های `integrity` و `crossorigin` را دست‌نخورده نگه می‌دارد | آزموده نشده. اگر ویژگی‌ها را بردارد یا برچسب‌ها را پاک کند، بارگذار جبران می‌کند (سه حالت آخر جدول بالا) |
| آیا ویرایشگر مطلب هنگام ذخیره کلاس‌ها و ویژگی‌های `data-` را نگه می‌دارد | آزموده نشده؛ بررسی پس از انتشار مقاله‌ی ۱ در کیت گذاشته شده است |
| آیا روش یک‌جای قالب بین سه زبانه پخش می‌شود | آزموده نشده؛ برای همین روش سه‌تکه راه اصلی است |
| خروجی واقعی برچسب‌های بلاگفا، نشانی‌ها، تبلیغ و اسکریپت‌هایی که بلاگفا به صفحه اضافه می‌کند | آزموده نشده؛ پیش‌نمایش آن‌ها را از روی راهنمای رسمی و صفحه‌های عمومی بلاگفا شبیه‌سازی می‌کند |
| دسترسی بازدیدکنندگان ایرانی به jsDelivr از اینترنت همراه و خانگی | آزموده نشده؛ فقط از ۸ نقطه‌ی مرکز داده |
| پنجره‌ی نظرها روی دامنه‌ی بلاگفا | آزموده نشده |
| مرورگرهای دیگر (Firefox، Safari) و گوشی واقعی | آزموده نشده؛ فقط Chromium در دسترس بود |
| کارایی روی کارت گرافیک واقعی | آزموده نشده؛ این محیط کارت گرافیک نرم‌افزاری دارد و نتیجه‌اش بدبینانه است |

این موارد با تصویرهای پنل واقعی بلاگفا تأیید شدند و کیت و راهنماها بر پایه‌شان اصلاح شدند: سه زبانه‌ی ویرایش قالب و دکمه‌ی «ثبت و بازسازی وبلاگ»، پیام خطای حجم، دکمه‌ی «منبع» ویرایشگر، سقف چهار برچسب با جداکننده‌ی `,` یا `+`، انتخاب موضوع از «تعاریف موضوعات»، و شکل نشانی `/page/…` صفحه‌های جداگانه.

## آزمون روی وبلاگ منتشرشده

هنوز انجام نشده، چون قالب آینده‌نگار روی وبلاگ نصب نشده است. پس از نصب و انتشار، صفحه‌ی اول، مقاله‌ها و صفحه‌ی درباره از نشانی عمومی بررسی می‌شوند: کلاس‌ها و نشانی‌های jsDelivr قالب آینده‌نگار در صفحه، راه افتادن قالب، و نام سازنده. نتیجه همین‌جا ثبت می‌شود.

## اجرای دوباره

```bash
cd blogfa
npm run qa       # ساخت، پیش‌نمایش، همه‌ی آزمون‌های قالب درون‌خطی و قالب CDN، و کیت
npm run qa:cdn   # فقط پیش‌نمایش و آزمون‌های قالب CDN
```

آزمون‌های مرورگر به Playwright نیاز دارند؛ اگر جهانی نصب شده است، با `NODE_PATH=$(npm root -g)` اجرا کنید. نتیجه‌ی ماشینی هر آزمون در پوشه‌ی `quality/` است.
